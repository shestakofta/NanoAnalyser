# CLAUDE.md — NPA (NanoParticle Analyzer)

Отвечай и пиши комментарии/тексты интерфейса **по-русски**. Предпочитай существующие методы с источниками; если своё — так и скажи.

## Суть
Настольная программа (Python + tkinter) для ПЭМ-снимков порошков наночастиц металлов (основной материал — W, проверялось также на Al). Команда разрабатывает катодные матрицы для СВЧ-электроники из наночастиц W. Главная величина — **доля массы модифицированных (крупных) частиц** по снимку и серии.
Классы: `mod` — модифицированные (крупнее отсечки `d_cut`, по умолчанию 25 нм); `agg` — агломераты первичных частиц (круги); `irr` — НФ, тела неправильной формы (масса прибавляется к агломератам); `del` — удалённые.
Версия: `APP_VERSION = "4.1.ml"` в `app.py`. **Номер версии не меняй без прямой просьбы.**

**Структура `res`** (главный объект): `s` — нм/пиксель; `shape`; `D` (float16, затемнение — нужно для пересчёта после правок); `m_all`, `valid`; `objects` — список dict (`id`, `cls`, `auto_cls`, `pix`=(ys, xs), `cx`, `cy`, `cut`, `from_circle`, признаки); `objmap` (id объекта на пиксель); `circles` — кортежи **`(y, x, d_нм, id_агломерата)`**: координаты в пикселях, диаметр в нм; `agg`, `comps`; `edit` — ручные правки (`del_mask`, `ucircles`, `uregions`, `ml_scratch`). Массы не хранятся в `res` при обработке: их считает `compute_masses(res, density)`, поэтому плотность и галочку «оценка глубины» можно менять без повторной обработки.
В ядре порядок координат — **(y, x)**; в JSON набора ML — `x, y, r` в пикселях.

**Поток в GUI.** Обработка идёт в `ProcessPoolExecutor` (по снимку на процесс; `analyze_image` должна оставаться top-level и picklable; `mp.freeze_support()` в `__main__` обязателен для собранной версии). Фоновые потоки **не трогают Tk**, а кладут в `self.queue` кортежи `(kind, path, data)`: `done`, `error`, `finished`, `preview`, `edited`, `toggled`, `mljob`, `job_error`. `_poll_queue` разбирает их в главном потоке.
Правки: инструменты кладут операции в `self.pending[path]`; Enter или «Применить» запускает `npc.apply_edits` в потоке. `self.hist` хранит до 3 снимков `res` для Ctrl+Z после применения.
Состояние ML-разметки снимка — `res["ml"]` (`base` — авто-круги при обработке, `doubt`, `region`, таймер).

**Пайплайн `analyze_image`:**
1. Масштаб из TIFF Olympus/SIS или по линейке (меряется полоса, а не рамка).
2. Фон от светлой плёнки, шум по фону.
3. Вещество: гистерезис `k_hyst_lo/hi` × шум, граница по `contrast`; `film_mask` вырезает тёмные ступеньки подложки.
4. Кандидаты в крупные тела, уточнение края на 25 % (`edge`), `classify2`.
5. `update_agglomerates`: всё остальное вещество — агломераты, в них круги v8. Круг ≥ `d_cut` не может быть первичным (его тело классифицируется заново).

**Массы:**
- mod — сплошной эллипсоид (c = b);
- НФ — эллипсоид × 0,74;
- агломераты — плоско (сумма видимых шаров) и с оценкой глубины N = 1,15·(S/Aₚ)^1,09 (Köylü 1995).

## Принятые решения (и отвергнутое)
- **Круги v8 вместо баланса площадей** (v4). Подобраны по ручной разметке Al: F1 с человеком ≈ 0,63, у двух людей между собой ≈ 0,70. Правило баланса площадей отвергнуто: оно уводит от людей.
  Проверено и **отвергнуто**:
  - уменьшение радиуса крупных кругов;
  - PCM / EDM-SBS как проверка;
  - фон полиномом;
  - модель цепочек как замена отбора;
  - удаление «круга-покрышки».
  Принято правило: крупный круг (≥ 1,3 медианы) ставится только при крае ≥ 1,5 шума.
- **classify2 (4.1)** заменил правила по выпуклости/контрасту (старые ключи `sol_hi`, `circ_min`… остались в `DEFAULTS` только для чтения старых файлов настроек). Совпадение с визуальной разметкой 1160 тел: 82 % против 75 %.
- **ML**: сначала был отложен («калибровать математику»). Решение 2026-10-20 — собирать набор в самой NPA (блок ML) и обучать модель «центр + радиус» (CircleNet, ResNet-18/34) с запуском в NPA через ONNX Runtime. Разметка и обучение идут на разных ПК, поэтому набор переносится папкой или zip (`pack_dataset` / `merge_archive`, дедупликация по sha1, у одного разметчика более новая разметка заменяет старую).
- **Круги для ML можно ставить любым инструментом**, «круг по 3 точкам» — обычный инструмент раздела «Редактировать».
- **C++ отвергнут**: ~70 % времени уже в скомпилированных библиотеках. Путь — оптимизация на Python (×2–3) плюс параллельность по снимкам.
- **PyInstaller onedir**, не onefile: onefile запускается на 10–20 с дольше.
- **Один `app.py` для Windows и macOS**: отличия через `IS_MAC`, `FS()` (шрифты ×4/3 на Mac), `MOD`. На Mac добавлены Cmd-сочетания и Cmd+колесо для масштаба, правая кнопка = `Button-2` / Ctrl+щелчок; `btn_meas` — `ttk` Toolbutton, потому что Aqua игнорирует цвета `tk.Checkbutton`.
- **Колесо левой панели** — единый `bind_all`-маршрутизатор `_panel_wheel` с проверкой `winfo_containing`. Старый вариант с `<Enter>/<Leave>` отвергнут: Leave срабатывал при заходе на дочерние виджеты. Шаги тачпада накапливаются в `_wheel_steps`; Combobox и Spinbox не меняют значение от колеса, пока не в фокусе (`_guard_wheel`); `<TouchpadScroll>` (Tk 9) подключается в try.
- **Число процессов по умолчанию**: min(ядра−1, (RAM−2 ГБ)/0,75 ГБ).

- Комментарии, докстринги и все тексты интерфейса — по-русски, простыми словами. Имена в коде — английские и короткие: `s` (нм/пикс), `D` (затемнение), `m` (маска), `res`, `P` (параметры), `cv` (канвас).

- При каждом изменении функционала обновлять `README.md`: раздел «Что нового в версии …» и соответствующий раздел инструкции. Источники методов указывать в докстринге модуля.
- Весь прежний функционал сохранять. Пасхалка «Флаг Нигерии» в меню графика (`_is_flag`) — намеренная, не удалять.
- Поддерживаемый Python — 3.10–3.12. Зависимости — `requirements.txt`.

## Проверка
Автотестов в репозитории нет. Изменения проверялись GUI-сценариями под Xvfb (вне репо):
- создать `App()`, подставить заглушки вместо `filedialog`/`messagebox`;
- загрузить готовые `res`, сгенерировать события мыши и колеса;
- сделать скриншот.

Минимум перед сдачей:
- `python -m py_compile *.py circ8/*.py`;
- запуск `python app.py` и обработка 1–2 снимков;
- для правок ядра — сравнение числа mod-частиц и кругов до/после на тех же снимках (обработка W12 ≈ 87 с на одно ядро).

## Машинное обучение (основной план работ)
Источник: документ «ТЗ на разметку снимков и план машинного обучения» (Claude Docs, 2026-10-20, ТЗ версии 1.0). При расхождении с этим разделом прав документ; изменения ТЗ — только с новой версией (`TZ_VERSION` в `ml_annot.py`).

**Цель.** Модель находит **центры и радиусы первичных частиц** и заменяет или дополняет этапы 1–3 v8 (кандидаты, формула, жадный отбор). Фон, контур, `classify2`, правила после кругов (круг ≥ `d_cut` не первичный, центр внутри контура и т. д.), массы и отчёты не меняются. Модель отдаёт тот же список кругов `(y, x, d_нм)`, дальше идёт прежняя цепочка.
Ориентиры: v8 совпадает с людьми на F1 0,61–0,63, люди между собой — 0,70 (это потолок). Реалистичная цель — 0,65–0,70, без гарантии.

**Модули (М1–М6) и их состояние:**
| Модуль | Что делает | Где работает | Состояние |
|---|---|---|---|
| М1. Режим разметки | правка v8 или «с нуля», «?», зона, таймер, JSON | NPA, блок «Разметка для обучения (ML)» | **сделано в 4.1.ml**, кроме импорта старой разметки Al (PNG с кругами) и автосохранения |
| М2. Проверка набора | проверка файлов, наложения для просмотра, согласие разметчиков, сводка | отдельный скрипт | не начат, нужен первым (калибровка) |
| М3. Подготовка данных | масштаб, нарезка, целевые карты, аугментация | ПК с GPU | не начат |
| М4. Модель и обучение | CenterNet/CircleNet на PyTorch | ПК с GPU | не начат |
| М5. Встраивание | `.onnx` через ONNX Runtime, выбор «v8 / модель» | NPA | после приёмки модели |
| М6. Отчёт о сравнении | F1 с каждым разметчиком, Σd³, ДИ для v8, модели и гибрида | скрипт | к пилоту |

**Где писать код.** М2–М4 и М6 — отдельная папка скриптов (например, `ml_tools/`), импортирует только `ml_annot` и `numpy`/`torch`. Это предложение: папки пока нет. `app.py` эти скрипты **не импортирует**, иначе PyInstaller затянет PyTorch в сборку. В сборку попадают только М1 (`ml_annot.py` + блок в `app.py`), М5 и файл модели.

**Данные (формат `npa-annot-1`, реализован в `ml_annot.py`):**
- папка набора: `images/` (копии снимков, дедупликация по sha1), `labels/<разметчик>/<снимок>.json`, `manifest.csv` (`;`, utf-8-sig, пересоздаётся `rebuild_manifest`), `README.txt`;
- в JSON: координаты в **пикселях исходного снимка**, x вправо, y вниз; `nm_per_px`, `objects`: P — `{shape:"circle", class:"P", x, y, r, doubt}`, M/I — многоугольники по маскам объектов;
- `region` — зона, где размечены **все** частицы; `ignore` — линейка; `mode` — `corrected` (правка v8) или `scratch` (с нуля); `stats` (`auto_kept`, `auto_removed`, `added` из `compare`); `time_min`;
- по ТЗ ещё нужны `splits.csv` (снимок; материал; серия; нм/пикс; train/val/test) и `annotators.csv` — их пока нет, делать в М2/М3;
- разметка и обучение идут на разных ПК: перенос `pack_dataset` / `merge_archive` (у одного разметчика более новая разметка заменяет старую, защита от zip-slip). Формат менять только с новой версией `FORMAT` и обратной совместимостью чтения.

**Набор:**
- ~200 снимков (≈10 000 частиц), ~45 ч разметки:
  - 43 Al со старой разметкой — проверить по ТЗ;
  - ~127 новых W/Al — правкой v8;
  - **30 тестовых** (20 W, 10 Al) — двое разметчиков, с нуля, независимо.
- Покрыть размер пикселя < 0,25 / 0,25–0,5 / 0,5–1 нм (≥ 30 снимков каждого); ≥ 20 % трудных снимков.
- Тест и проверочный набор (~15 % обучающих) выделять **целыми сериями** (день съёмки, образец), иначе оценка завышена.
- 13 снимков Al с двумя разметчиками — только дополнительная проверка: по ним настраивалась v8.
- Число 200 уточняется кривой обучения на пилоте (25/50/100 %): если от 50 к 100 % F1 растёт > 0,01 — размечать дальше.

**Правила разметки, важные для кода:**
- круг по внешнему краю частицы;
- обрезанная краем кадра частица размечается, если в кадре ≥ 50 % площади (круг выходит за кадр);
- минимум max(8 пикс, 3 нм);
- «?» ≤ 10 % кругов: при обучении и оценке «?» и всё вне `region` **не штрафуются** ни как ошибка, ни как попадание;
- круг внутри круга допустим.

**Обучение (М3–М4):**
- пересчёт к 0,5 нм/пикс;
- фрагменты 512×512 с перекрытием;
- цели — гауссова карта центров, карта радиуса, поправка центра;
- ResNet-18/34 с предобучением на ImageNet и декодер, пачки 8–16, аугментация (повороты, отражения, яркость, контраст, шум), 100–200 эпох;
- лучшая эпоха — по проверочному набору с критерием **F1 − 0,3·|ln V|**, где V = отношение Σd³ к разметке; совпадение кругов — при IoU ≥ 0,4;
- железо: NVIDIA ≥ 8 ГБ (RTX 3060 12 ГБ+), 32 ГБ ОЗУ, Python 3.12 + PyTorch CUDA; прогон 1–3 ч, всего 10–30 прогонов;
- в этой облачной среде GPU нет: код писать и проверять на маленьких прогонах.

**Приёмка** (все три условия на 30 тестовых снимках; тест открывается один раз):
1. F1 выше v8 с **каждым** разметчиком, 95 % ДИ разности без нуля;
2. Σd³ к разметчикам 0,9–1,1;
3. не хуже v8 отдельно на W и на Al.

Проверяются два варианта встраивания:
- **замена** — круги модели вместо этапов 1–3 v8, из последующих правил оставляются полезные;
- **гибрид** — оценка модели как ещё один признак формулы v8.

Если модель не лучше: набор идёт на перенастройку весов и порогов v8 под W (сейчас они подобраны только на Al).

**М5 в NPA (план):**
- `onnxruntime` — необязательный импорт; без него и без файла модели остаётся v8;
- выбор «v8 / модель» в «Расширенных настройках» (`ADV_KEYS`);
- модель (20–50 МБ) лежит рядом с программой; на macOS — в `resources/` через `--add-data`;
- сборка вырастет на 60–90 МБ; нужны колёса onnxruntime для Windows x64 и macOS arm64/x86_64;
- вывод: масштаб 0,5 нм/пикс → фрагменты → склейка → обратный пересчёт в пиксели снимка → `(y, x, d_нм)` в `_finish_circles` и далее как у v8;
- цель по времени — 1–5 с на снимок на CPU;
- работу модели держать в процессе обработки (`ProcessPoolExecutor`), не в GUI-потоке.

**Этапы** (≈10–14 недель):
1. **Подготовка**: ТЗ, лист примеров, М1; калибровка — 5 снимков размечают все, согласие ≥ 0,70 → ТЗ 1.1.
2. **Пилот**: ~60 снимков, М2–М4, первая модель и кривая обучения.
3. **Основная разметка**: до 170 обучающих + 30 тестовых; набор замораживается (`dataset_v1`).
4. **Обучение и сравнение** (М6).

## Подводные камни
- Плоская масса агломератов по v8 на Al на 10–20 % выше ручной (лишние крупные круги на скоплениях). Слабые места — плотные «грозди» (снимки W № 5, 8).
- Бледным снимкам Al нужно шумоподавление 2,0 (по умолчанию 1,0 — под W).
- Снимки с пикселем > 1,2 нм берут размеры первичных из более детальных снимков партии (`pooled_primary_sizes`).
- `<Double-Button-1>` на канвасе перехватывает быстрые щелчки: инструменты с повторным щелчком (`add_c3`, `ml_doubt`) обрабатываются в `_double_press`.
- Если `ttk.Combobox` / `Spinbox` в левой панели создаются после старта, их надо пропустить через `_guard_wheel`.
- На macOS Tk 8.6 щипок не даёт событий; дельта колеса — строки (±1…10), в Windows — 120 за щелчок.
- Копирование собранной папки `dist` на дешёвую флешку портило файлы (ошибки Tk при запуске). Переносить архивом.
- `res["D"]` хранится во float16 ради памяти; для расчётов приводить к float32.
